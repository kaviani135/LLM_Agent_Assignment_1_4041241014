# LLM Agents – Assignment 1

## Overview

This project implements a reasoning agent for numerical, logical, and constraint-based questions. It uses a local Ollama model when model reasoning is needed and Python tools for calculations or constraints that can be checked directly. The program returns only the final answer in the JSON format required by the assignment.

The implementation is intended to work on new questions as well as the public examples. The public questions are kept in the test folder and are not loaded by the runtime agent.

## Project files

| File | Description |
|---|---|
| `main.py` | Reads the input JSON and writes the output JSON. |
| `agent.py` | Contains the Ollama client, prompt flow, routing, verification, and recovery logic. |
| `tools.py` | Contains calculation and problem-solving tools, including arithmetic, linear equations, sets, schedules, grids, and finite constraint problems. |
| `requirements.txt` | Lists the Python requirements. The current implementation uses only the standard library. |
| `tests/test_agent.py` | Unit and regression tests for the agent and tools. |
| `tests/test_hidden_style.py` | Tests with changed values, alternative wording, and cases where a solver should abstain. |
| `tests/public_questions.json` | The ten public development questions. |
| `tests/run_public.py` | Runs the public questions and checks the output format. |
| `input.json` | A small example input for testing the command-line interface. |

## Requirements

- Python 3.10 or newer
- Ollama installed and running locally
- The model required for evaluation downloaded in Ollama

No additional Python packages are currently required. The model must be available locally before running the program without an internet connection.

## Running the program

Run the following commands from the project folder in PowerShell. Set `OLLAMA_MODEL` to the exact model tag provided for the evaluation:

```powershell
ollama list
$env:OLLAMA_MODEL = "<exact-model-tag>"
python -m pip install -r requirements.txt
python main.py --input input.json --output output.json
Get-Content .\output.json -Raw -Encoding UTF8
```

The required command-line interface is:

```powershell
python main.py --input input.json --output output.json
```

The input file contains an `id` and a `problem` field. The output contains the same `id` and an `answer` field. The `answer` field is reserved for the final answer; explanations or extra text should not be included.

Example input:

```json
{"id":"example_001","problem":"What is 2 + 2? Return only the integer."}
```

Example output:

```json
{"id":"example_001","answer":"4"}
```

If `OLLAMA_MODEL` is not set, the program checks the models available from the local Ollama service and tries to select an installed Qwen 27B model. For a predictable evaluation setup, it is better to set `OLLAMA_MODEL` to the exact tag announced by the instructor. The program does not download models automatically.

## How the agent works

1. **Check the question type.** The program first checks whether the question matches a supported problem family, such as arithmetic, set counting, scheduling, a grid path, or a finite constraint problem. If the wording contains conditions that the tool does not support, the tool should abstain instead of guessing.
2. **Choose a solving path.** In `auto` mode, straightforward problems can be solved directly with Python tools. For some logic and constraint problems, an installed larger model is also used to interpret the question. `model-first` always tries the model first, while `fast` uses a complete deterministic result when one is available.
3. **Create and check a plan.** When the model is used, it receives the original question and is asked for a structured response. If it returns a supported calculation or constraint plan, the program checks that plan against the question and runs it with the corresponding Python tool.
4. **Verify the result.** A result calculated by a supported tool takes priority over a conflicting model answer. The program does not execute Python code generated by the model and does not use `eval`.
5. **Handle failures.** Model calls and recovery attempts are limited. If Ollama times out or cannot load the model because of insufficient memory, the program can use a deterministic result already found by the tools. A fallback answer is not treated as proof that the model completed the task.

## Configuration

The main settings can be changed with environment variables:

| Variable | Default | Purpose |
|---|---:|---|
| `OLLAMA_MODEL` | Automatic local selection | Selects the exact Ollama model tag. |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | Local Ollama address. Only localhost addresses are accepted. |
| `AGENT_STRATEGY` | `auto` | `auto`, `fast`, or `model-first`. |
| `AGENT_MAX_CALLS` | `2` | Maximum number of model calls (limited to 1 or 2). |
| `AGENT_CALL_TIMEOUT` | `120` | Maximum time for one model call, in seconds. |
| `AGENT_TOTAL_TIMEOUT` | `150` | Overall time budget for model calls, in seconds. |
| `AGENT_NUM_CTX` | `8192` | Ollama context size. |
| `AGENT_NUM_PREDICT` | `768` | Maximum number of generated tokens for the main call. |
| `AGENT_TEMPERATURE` | `0` | Generation temperature. |
| `AGENT_THINK` | `off` | Enables or disables thinking mode where supported by the model. |
| `AGENT_STRICT_VERIFICATION` | `0` | If set to `1`, the program does not return an unverified model-only fallback. |
| `AGENT_DIAGNOSTICS` | Off | If set to `1`, diagnostic messages are written to stderr. |

The time and call limits used for evaluation should follow the instructor's requirements. A larger context or more model calls can increase runtime, so these settings should be checked with the actual evaluation model and hardware.

## Tests

Run the unit tests with:

```powershell
python -m unittest discover -s tests -q
```

Run the public development questions with:

```powershell
python tests/run_public.py
```

The unit tests include fixed regression cases, generated input variations, and cases where the tools should reject unsupported conditions. Some tests use a fake model interface so that model-call limits and error handling can be tested without running Ollama.

The public runner checks that each response is non-empty and has the expected JSON format. Its `OK` status is not an accuracy score. The unit tests and public runner do not measure accuracy on the instructor's hidden questions.

## Local execution and safety

All model inference is sent to the local Ollama service. The client accepts only `localhost` or `127.0.0.1`; it does not use a cloud model API. The calculation tools use restricted parsing and bounded operations. Model-generated code is not executed. After Python, Ollama, and the required model are installed, the program can run without an internet connection.
